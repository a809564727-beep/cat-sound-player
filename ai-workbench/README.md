# AI副业接单与交付工作台

一个给 AI 副业从业者长期使用的业务管理系统：从**客户 → 需求 → 报价 → 执行 → AI 工具选择 → 交付 → 修改 → 收款 → 售后 → 数据统计**，一站式管理。

- 打开即用：内置真实感示例数据（10 个客户、15 个项目、14 种服务、20 个 AI 工具），不是空白页面
- 数据保存在本机浏览器，刷新、重启都不会丢；支持一键导出 / 导入 JSON 备份
- 中文界面，桌面端与手机端均可使用，支持浅色 / 深色 / 跟随系统主题
- 代码按"领域逻辑 / 存储适配器 / 页面"分层，方便以后升级为云端 SaaS

### 工程质量

- TypeScript 严格模式，`tsc` 零报错；页面无控制台错误
- 所有表单都有校验与错误提示；所有删除操作都有二次确认
- 列表都有空状态；保存失败（如存储空间满）会在顶部提示
- 手机端（390px 宽）所有页面无横向溢出，弹窗在手机上以底部抽屉形式出现
- 35 个单元测试 + 17 个端到端测试（Playwright，含手机端）

## 安装与启动

需要 **Node.js 20 或更高版本**。

```bash
cd ai-workbench
npm install

# 开发模式（修改代码会热更新）
npm run dev
# 打开 http://localhost:3000

# 日常使用推荐：生产模式（更快）
npm run build
npm run start
# 打开 http://localhost:3000
```

第一次打开会自动加载示例数据。想从零开始：**设置与备份 → 清空业务数据**（会保留服务库和工具库）。

### 测试

```bash
npm run typecheck   # TypeScript 类型检查
npm test            # 单元测试（Vitest）
npm run build && npm run test:e2e   # 端到端测试（Playwright，会自动启动服务，端口 3100）
npm run test:all    # 以上全部
```

第一次运行端到端测试前，如果本机没有 Playwright 浏览器，需要先执行 `npx playwright install chromium`。

## 数据存储方式

- 所有数据存在浏览器 `localStorage` 的 `ai-workbench:data` 键下，是一个 JSON 对象（`WorkbenchData`），包含 `clients`、`projects`、`services`、`quotes`、`payments`、`tools`、`todos`、`settings` 和 `schemaVersion`
- 每次修改后自动保存；页面加载时通过 `migrateData()` 校验并补齐缺失字段，老版本数据可以平滑升级
- 如果本地数据损坏无法读取，会先把原始内容另存到 `ai-workbench:data:corrupt-<时间戳>`，再加载示例数据，**不会悄悄覆盖你的数据**
- 主题、项目视图（列表/看板）等界面偏好单独存放，不混入业务数据
- **注意**：数据只在当前浏览器中。清除浏览器数据、换浏览器或换电脑都会看不到数据，请定期在「设置与备份」中导出 JSON 备份

### 统计口径

- **收入**：按实际收款日期统计，退款计为负数
- **订单 / 成交**：状态为 进行中、待客户审核、修改中、已交付、已完成 的项目；订单日期取开始日期（没有则取创建日期）
- **平均客单价**：成交项目的成交价平均值（没有成交价时用报价）
- **订单转化率**：成交项目 / 全部项目
- **项目完成率**：已完成 / 成交项目
- **付款状态**：已收 ≥ 应收 → 已付款；只收过定金 → 已付定金；收过其他款项 → 部分付款；有退款且实收为 0 → 退款

## 为商业化预留的设计

当前版本刻意保持简单，但关键位置都留了扩展点：

| 未来功能 | 现在的准备 |
| --- | --- |
| 云数据库 / 多设备同步 | 所有读写都经过 `StorageAdapter` 接口。实现一个 `ApiAdapter` 或 `SupabaseAdapter` 传给 `WorkbenchProvider` 即可，页面代码不用改 |
| 多租户 / 团队 | 实体都有 `id / createdAt / updatedAt`，迁移时加一个 `workspaceId` 字段；`migrate.ts` 已有版本迁移机制 |
| 用户登录 / 微信登录 | 在 `providers.tsx` 外层加一个 AuthProvider，按用户加载对应数据即可 |
| AI API 推荐 | `recommend()` 的输入输出（`RecommendInput` / `Recommendation`）是稳定接口，可实现 `aiRecommend()` 调用 Claude 等模型，规则引擎作为离线兜底 |
| 服务端 API | `lib/domain/` 下全是无 React 依赖的纯函数，可以直接放到 API Route / Server Action 中复用 |
| 在线支付 / SaaS 订阅 | 收款模型已有 `method / kind / paidAt`，可以新增支付渠道并由支付回调自动生成收款记录 |

## 未来升级方向

1. **云端同步**：接入 Supabase / PostgreSQL，实现多设备同步与自动备份
2. **AI 能力**：用大模型根据客户聊天记录自动整理需求、生成报价建议与交付说明
3. **客户沟通模板**：报价、催款、交付、售后回访的话术模板，一键复制
4. **文件上传**：交付物直接上传到对象存储，并生成客户可访问的交付页面
5. **成本与利润**：记录 AI 订阅、算力积分等成本，计算每单利润与时薪
6. 日历视图、截止日期浏览器通知、PWA 离线安装、多币种、发票

## 已知限制

- 数据只在本机浏览器中，没有多设备同步（请定期导出备份）
- 交付物只记录链接 / 文件位置，不上传文件本身
- 报价单的 PDF 通过浏览器"打印 → 另存为 PDF"生成
- AI 推荐是规则引擎，不是真正的大模型
